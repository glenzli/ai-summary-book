# 第七章 怎样分析模型中的概率

概率分析的目标不是生成尽可能多的图表，而是回答一个可判定的问题：差异发生在数据、基础模型、解码器还是完整系统？本章给出一套针对大模型的最小实验方法。

## 7.1 先写清分析对象

一个完整问题至少包括：

- 模型与 checkpoint；
- tokenizer、chat template 和实际 token 输入；
- 分析层：原始 logits、处理后分布、采样输出或系统返回；
- 输入总体或数据集；
- 随机重复单位；
- 指标和容许误差。

“比较两个模型谁更自信”不够明确。应改写为例如：“在固定多选数据集、统一选项措辞和 template 下，比较正确选项归一化概率的 NLL 与 reliability curve。”

## 7.2 Logit 侧分析

对固定候选 $a,b$，可用 logit difference

$$
\Delta_{a,b}(x)=z_a(x)-z_b(x)
$$

避免词表其余项的归一化影响。若候选由多个 token 组成，应计算完整序列 log likelihood，而不是只比较首 token。

分析提示变量 $v$ 时，构造配对输入 $x_i^{(0)},x_i^{(1)}$，观察

$$
d_i=\Delta(x_i^{(1)})-\Delta(x_i^{(0)}).
$$

配对差可以减少样本内容本身的方差，但只能把差异归因于所控制的输入变换；若变换同时改变语义和格式，解释仍然混杂。

## 7.3 候选集规范

固定选项实验应控制：

- 标签 token 是否都是单 token；
- 选项顺序是否随机化；
- 前导空格、大小写与标点；
- 是否包含 EOS；
- 是比较标签概率还是完整答案文本；
- 候选外概率质量如何处理。

若只对候选内重新归一化

$$
\tilde q(a_k)=
\frac{q(a_k)}{\sum_jq(a_j)},
$$

报告中应明确这是条件化分布。原模型可能把大部分质量给了候选外文本。

## 7.4 重复采样估计行为概率

固定模型和解码协议，对同一输入独立采样 $n$ 次。事件 $A$ 的频率估计为

$$
\hat p=\frac1n\sum_{i=1}^n\mathbf1\{Y_i\in A\}.
$$

若样本近似独立同分布，标准误差估计为

$$
\widehat{SE}(\hat p)
=\sqrt{\frac{\hat p(1-\hat p)}{n}}.
$$

当 $p$ 接近 0 或 1、样本很少时，不宜机械使用正态近似区间；可以报告 Wilson 或精确二项区间。更重要的是先定义事件 $A$，例如“事实正确”需要盲评协议或可执行 verifier。

## 7.5 独立性经常被破坏

以下情况使重复输出不再是简单 iid 样本：

- 缓存或会话记忆跨请求保留；
- 服务模型在实验中途更新；
- rate limit 或负载改变解码配置；
- 随机 seed 重复；
- 多个样本共享同一生成后再改写；
- 评审者看到前面样本后改变标准。

应随机化请求顺序、记录时间与版本，并在统计模型中把共享 prompt、模型运行和评审者视为可能的聚类层级。

## 7.6 比较两种系统

若同一组输入同时评测系统 A、B，使用配对差

$$
\hat\delta
=\frac1n\sum_{i=1}^n
(s_{i,A}-s_{i,B}).
$$

对输入单位进行 paired bootstrap 可以估计差值区间。若每个输入又有多次采样，应保持层级结构：bootstrap 输入，再在输入内保留或重采样运行，避免把所有输出错误当作完全独立。

除了区间，还应报告效应量与原始失败类型。大样本可以让极小差异“显著”，但未必具有工程意义。

## 7.7 分离基础模型与解码器

要判断行为差异来自哪里，可按顺序比较：

1. 实际 input token IDs；
2. 原始 logits 或候选 logit difference；
3. temperature/penalty 后 logits；
4. top-k/top-p 后支持集与概率；
5. PRNG 状态与被选 token；
6. 后过滤和返回文本。

如果原始 logits 已不同，问题在模型输入、权重或数值前向；如果只在截断后不同，问题在解码配置；如果 token 相同但显示文本不同，问题在反分词或客户端层。

## 7.8 训练因素实验

研究数据混合、随机 seed 或后训练方法时，至少要有多个训练运行。设配方 $r$、训练 seed $j$、评测输入 $i$ 的分数为 $Y_{rij}$。一个简单分层模型是

$$
Y_{rij}=\mu+\alpha_r+b_{rj}+u_i+\varepsilon_{rij},
$$

其中 $\alpha_r$ 是配方效应，$b_{rj}$ 是同配方下运行差异，$u_i$ 是输入难度。只有每个配方一个 checkpoint 时，配方差异与 seed 差异完全混杂。

训练成本很高时可以减少运行数，但必须诚实地把结论写成个案比较，而不是稳定的算法效应。

## 7.9 校准实验

一个可信的校准流程是：

1. 固定事件和标签；
2. 用训练集训练模型；
3. 用独立 calibration set 拟合 temperature 或映射；
4. 在未参与拟合的 test set 上报告 NLL、Brier、reliability 与 ECE；
5. 按时间、领域、难度和子群体分层检查；
6. 在分布转移后重新评估。

同一测试集上选择校准方法再汇报结果会产生乐观偏差。

## 7.10 开放回答的语义事件

若事件是“回答表达法国首都为巴黎”，需要一个映射

$$
g:\text{text}\to\{0,1,\text{uncertain}}.
$$

$g$ 可以由规则、数据库、人工或模型评审实现。每种实现都有误差，应抽样人工复核，并报告 uncertain 如何处理。若用同一家族模型生成又评判，相关错误可能使成绩虚高。

## 7.11 首分歧而非只看终点

对两条自回归轨迹，定义首次不同 token 位置

$$
\tau=\min\{t:y_t^{(A)}\ne y_t^{(B)}\}.
$$

再比较 $\tau$ 前一时刻的输入、logits、处理后概率和随机数。最终文本可能相差很大，但真正原因通常位于第一个分叉点。

对扩散模型，可比较初始噪声、条件编码和每个去噪步状态；对工具系统，则比较首次不同的调用候选、权限结果或工具返回。

## 7.12 多重比较与探索

若同时测试大量提示、层、token 和指标，偶然极值必然增多。探索阶段可以广泛扫描，但确认性结论应：

- 预先指定主要指标或使用独立确认集；
- 报告测试数量与选择过程；
- 采用适当多重比较控制；
- 在新模型或新数据上复验；
- 发布负结果与不稳定结果。

一张最醒目的 attention heatmap 或 logit 峰值不是总体效应的证据。

## 7.13 最小实验记录

建议保存：

- 数据版本、样本 ID 与预处理；
- 模型、tokenizer、template 和服务版本；
- 原始请求与规范化后的实际输入；
- 全部解码参数和 stop 条件；
- seed、重复次数与请求时间；
- 评分器、评审协议及其版本；
- 原始逐样本结果，而不只保存平均数。

这些记录服务于概率结论的可检查性，不要求为每次研究构造庞大的形式合同。

## 7.14 本章结论

有效分析始于明确概率对象和随机重复单位，然后用配对设计、分层重复与适当区间区分输入、模型、解码和系统效应。复杂统计模型不能弥补混杂设计；逐步 trace 和原始数据往往比额外术语更能解释问题。
