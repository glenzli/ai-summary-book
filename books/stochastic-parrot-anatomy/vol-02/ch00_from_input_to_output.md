# 导论 从输入到输出：一张执行地图

卷一描述了模型怎样设计和训练。本卷只观察一件事：当用户按下发送键后，一次具体输出怎样发生。

贯穿案例使用一个简单请求：

> 请用一句话解释为什么天空通常呈蓝色。

最终屏幕上出现一句中文回答。中间却至少经历：应用组装上下文、文本编码、tokenize、模型 prefill、逐步产生 logits、选择 token、更新 KV cache、判断停止、detokenize、流式传输和界面显示。若模型调用工具，过程还会离开模型，进入另一个有自己状态和失败方式的系统。

本卷不先建立一套一般程序语义，再把模型塞进去。它从实际数据结构和事件顺序出发，只在需要区分对象时引入记号。

## 0.1 三个边界

一次输出至少有三个边界：

1. **应用边界**：用户界面、模板、检索、权限和服务配置；
2. **模型边界**：token 序列进入参数化前向计算，得到 logits 或其他模型输出；
3. **现实边界**：工具或执行器真正读取、写入、发送或移动对象。

“模型回答了什么”常把三者压成一句话。本卷会反复拆开它们，并始终沿一次运行的时间顺序说明。

## 0.2 一次运行记录什么

为了跟随执行，需要一条最小时间线：

```text
t0 user submits text
t1 application assembles context
t2 tokenizer produces token ids
t3 model finishes prefill
t4 first token is selected
t5..tn later tokens are selected and streamed
tn+1 stop condition fires
tn+2 bytes are displayed
```

每一步只记录理解过程所需的对象：输入、模型工件、关键配置、token、张量形状、选择结果和可观察事件。不会改变运行或解释的字段不进入这条时间线。

## 0.3 固定不等于随机

若模型权重、上下文 token、数值实现和选择规则全部固定，而且选择规则是 greedy，一次运行原则上可以完全确定。若使用随机采样，还需要随机源状态。若在线系统含动态检索、并发调度或工具返回，即使模型本身确定，系统输入仍可能变化。

卷二只说明这些随机入口位于哪里；“它们表示怎样的概率”是卷三的主题。

## 0.4 阅读路线

- 第一章把可见文字变成模型真正接收的 token 序列；
- 第二章跟随 prefill 和一次 Transformer 前向；
- 第三章从隐藏状态走到 logits 和一个候选 token；
- 第四章把单步选择扩展为完整自回归循环和 streaming；
- 第五章比较自回归、掩码迭代和连续去噪；
- 第六章说明工具调用何时离开模型边界；
- 第七章用三条完整时间线收束。

本卷的目标不是让每位读者实现推理引擎，而是让“模型生成了一句话”不再是一只黑箱动词。
