# 第三章：主线、依赖图和章节分解

目录可以按对象分类，却仍然没有阅读方向。“群、环、域、模”是一组相关标题，但读者不知道每章解决了前一章的什么问题。主线要求更强：每个章节都必须产出后文会使用的能力，同时只调用已经建立或明确外置的输入。

依赖图不是为了把书画得复杂，而是为了在写作前发现循环、孤岛和过载章节。图的节点粒度必须足以显示证明义务，又不能细到每个公式都是一个顶点。

## 3.1 节点、边与章节合同

**定义 3.1（主线依赖图）.** 主线依赖图 $G=(V,E)$ 的顶点是核心定义、主定理、关键例子和外部输入。若理解、构造或证明 $v$ 必须先取得 $u$，则置有向边 $u\to v$。

**定义 3.2（章节合同）.** 一个章节合同包含：允许输入、产生的对象与结果、承担的证明、贯穿例子、读者完成的操作以及留给后文的问题。章节正文可以自然叙述，合同则放在规划账本中。

章节标题不是合同。“条件期望”这一标题没有说明是只定义有限条件概率，还是要构造 $L^1$ 条件期望、证明唯一性与塔性质。

## 3.2 合法顺序与破环

**命题 3.1（线性阅读顺序与拓扑序）.** 有限主线依赖图存在一种使每条边都从较早节点指向较晚节点的线性阅读顺序，当且仅当该图无有向环。

**证明.** 若存在这样的线性顺序，有向环中取顺序最晚的节点；环上从该节点出发的边指向更早节点，与边必须向后矛盾。反之，有限无环图必有入度为零的节点：若每个节点都有入边，从任一点反复沿入边前进，由有限性必重复节点并形成环。删除一个入度为零节点后仍为有限无环图，归纳排列剩余节点，再把该节点置于最前，即得拓扑序。$\square$

教材中有三类表面循环：

1. **定义循环**：两个对象互相使用，需改成联合归纳定义或先给原始语法；
2. **证明循环**：定理 A 调用 B，B 又调用 A，必须寻找共同引理或同时归纳；
3. **叙事回访**：先给直观例子，后给严格定义，再回看例子。这不构成逻辑循环，只要第一次出现不承担未建立的证明责任。

## 3.3 节点粒度

过粗的节点“泛函分析基础”隐藏了定义域、自伴性和谱测度之间的依赖；过细的节点把每次代数变形都列入图，无法维护。实用标准是：若一个对象具有独立的定义、证明状态或外部来源，就应成为节点；纯粹的局部计算步骤保留在证明内部。

**案例 3.1（修复类型安全证明的隐边）.** 某章直接从 STLC 类型规则跳到 preservation，证明中写“由类型唯一性可得函数体有相应类型”。实际需要的是应用和抽象规则的反演，以及 beta 情形中的 substitution。修正后的依赖为

```text
语法与类型规则
  -> weakening
  -> inversion
  -> substitution
  -> preservation
语法与值定义
  -> canonical forms
  -> progress
preservation + progress -> type safety
```

类型唯一性是另一条结果，不能替代反演。依赖图使这一逻辑错误在扩写正文前就可见。

## 3.4 从图到章节

相邻且共享动机、证明技术和例子的节点适合放入同章。仅因名称相近而共享标题不够；例如强正规化和类型安全都谈“良类型项”，但证明技术分别是逻辑关系与操作语义归纳，完全可以把前者作为下一章或外部输入。

一个章节若包含过多互不连接的叶节点，通常是百科式堆积；若只有一个定义和一句定理，通常只是目录项。是否需要拆分应看章节合同能否形成“问题、对象、例子、结果、后续用途”的连续链，而不是按固定页数判断。

## 3.5 变更控制

新增核心节点时，要检查其所有入边是否已有来源、所有出边是否改变后文假设，并同步定理索引和来源账本。删除节点时则检查是否仍有悬空出边。图可以用 Markdown 文本维护；重要的是关系准确，不是绘图软件。

## 练习

**练习 3.1.** 为“测度、随机变量、期望、条件期望、鞅”画出节点级依赖图，并给出一种拓扑序。

**练习 3.2.** 给出一个主题并列但没有主线推进的目录，然后用章节合同将其重排。

**练习 3.3.** 判断“先用群作用解释对称性，第五章才正式定义群作用”是逻辑循环还是叙事回访，并列出使其合法的条件。
