# 附录 B：审计清单和验证模型

审计的目标不是制造更多勾选框，而是让不同类型的失败由合适方法发现。机械检查负责确定关系，内容审读负责数学与叙事判断，收口结论负责把二者合并。

## B.1 机械门禁

对目标目录至少检查：

1. 所有本地 Markdown 和资源链接存在；
2. 定理、定义、例子和习题编号无冲突；
3. 索引条目在正文有唯一位置；
4. 每个核心习题有对应解答；
5. 数学分隔符、代码围栏和 LaTeX 环境配对；
6. 不兼容宏、行尾空白和已禁止工作状态清零；
7. 变更只落在授权目录，未覆盖无关修改。

机械门禁失败时先修结构，不进入最终内容判定。通过时只记录“机械闭合”。

## B.2 章节内容矩阵

每章逐项登记“位置 + 证据”，不能只写是或否：

| 检查面 | 证据问题 |
|---|---|
| 问题入口 | 第一节前的具体问题是什么 |
| 对象类型 | 哪些定义给出了域、值域和等价口径 |
| 边界 | 零、空、奇异、无穷或失败情形在哪里处理 |
| 主张状态 | 每个核心结论如何终结证明责任 |
| 工作例 | 哪个例子实际执行了定义 |
| 证明依赖 | 代表性证明调用了哪些前项 |
| 外部输入 | 精确版本与来源链在哪里 |
| 读者检验 | 哪道题独立检查了章节输出 |
| 后续作用 | 本章哪些输出被下一章调用 |

缺少核心行时，该章不能仅凭篇幅或文件存在判闭合。

## B.3 证明责任工作表

对每个核心定理记录：

1. 把结论拆成存在、唯一、性质、自然性和边界等分项；
2. 为每一项标出证明中的责任点；
3. 列出所有外部输入和换序、极限、选择步骤；
4. 从前向后检查推导，再从结论反向寻找覆盖；
5. 检查定理是否比证明覆盖范围更强；
6. 检查后文是否按实际状态调用。

若证明需要未陈述的有限引理，补入正文；若需要新的大型理论，精确外置并调整主张状态。

## B.4 来源审计

逐个外部输入核对：正文编号、精确陈述、假设、用途、来源版本和定位是否一致。对一手论文核对题名、作者和年份；对专著核对版本与章节；对网页或标准记录稳定链接和版本日期。仅出现在总书目而没有输入映射的来源，不算完成定位。

## B.5 叙事与密度风险

以下信号要求人工复核，但不宜单独设为数学判据：

- 一章用数十行覆盖需要多个新对象和定理的主题；
- 连续章节具有同样标题骨架和段落节奏；
- 定义、定理和练习之间没有过渡或例子；
- 大量边界声明占据正文，却没有实际论证；
- 答案多为一句结论；
- 来源只有书名清单。

文本长度只能提示“大纲风险”。真正判定仍来自章节内容矩阵。

## B.6 全书判定规则

全书内容闭合要求：范围冻结单有效；所有核心章节矩阵无缺行；核心定理责任表完成；外部输入链可复查；学习目标有练习覆盖；机械门禁通过；没有已知未处理的数学错误。非核心增强可以列入后续版本，但不得伪装成当前阻塞项。

若任一核心项未满足，使用“内容收口候选”或“不通过”，并准确列出节点。审计日期和版本必须写入回执；后续实质修改会使旧回执失效。

## B.7 最小验证流程

在本仓库中，可以依次运行 OET 结构审计、教材叙事审计、系列链接与编号验证以及 `git diff --check`。命令名和参数由仓库脚本维护。审定文件记录输出摘要，同时列出人工抽查的定理编号；只粘贴脚本成功状态不满足 B.6。
