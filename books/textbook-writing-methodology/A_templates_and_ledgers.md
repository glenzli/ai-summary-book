# 附录 A：文件模板和账本格式

模板的用途是防止遗漏，不是让正文长成统一表格。以下格式适合规划文件、索引和审计账本；章节正文仍应按照问题、对象、例子和论证自然推进。

## A.1 最小文件职责

**原则 A.1（职责完整而非文件数量）.** 一套可维护教材至少要承担下列职责，但可以按规模合并文件：

| 职责 | 典型文件 | 必须回答的问题 |
|---|---|---|
| 范围与阅读合同 | `README.md` | 写给谁、到哪里、哪些不写 |
| 写作约束 | `SKILL.md` | 状态、符号和修改规则是什么 |
| 符号与术语 | `NOTATION.md` | 默认类型和局部例外是什么 |
| 来源与外部输入 | `SOURCES.md` | 输入版本在哪里、如何使用 |
| 主张索引 | `THEOREM_INDEX.md` | 每个核心结论是什么状态 |
| 依赖关系 | `DEPENDENCY_GRAPH.md` | 哪些节点依赖哪些输入 |
| 读者检验 | `SOLUTIONS.md` | 核心操作如何被独立核查 |
| 审定证据 | `CONTENT_CLOSURE_AUDIT.md` | 机械与内容检查分别得到什么 |

八个空文件不满足原则 A.1；一部三章小册也可以把相容职责合并到较少文件。

## A.2 范围冻结单

```markdown
# 范围冻结单

- 读者合同：
- 中心问题：
- 完成后操作：
- 核心对象：
- 终点结果或构造：
- 书内主线：
- 外部输入：
- 反范围：
- 每项完成证据：
```

“完成后操作”使用可观察动词，例如证明、计算、构造、比较和诊断；避免“了解”“熟悉”而没有检验方式。

## A.3 章节合同

```markdown
## 章节合同：第 n 章

- 问题入口：
- 允许输入：
- 新对象及类型：
- 内部证明：
- 外部输入：
- 工作例或贯穿案例：
- 读者操作：
- 后续输出：
- 未纳入边界：
```

章节合同属于规划账本，不应原样复制到正文成为固定栏目。

## A.4 主张账本

| 字段 | 内容 |
|---|---|
| 编号 | 稳定标识，例如 T4.2 |
| 陈述摘要 | 不替代正文完整陈述 |
| 状态 | `P`、`S`、`E` 或 `C` |
| 证明或输入位置 | 文件与节号 |
| 直接依赖 | 定义、引理、外部输入 |
| 下游调用 | 哪些结果使用它 |
| 审定证据 | 审读日期、检查重点 |

`P` 只表示完整书内证明；`S` 表示条件明确的推导、计算或可执行方案；`E` 表示外部输入；`C` 表示非定理判断。证明路线附在 `E` 后，不单独升级为 `P`。

## A.5 外部输入记录

```markdown
### EI-k：定理名

- 精确陈述：
- 全部假设：
- 正文用途：
- 一手或专著来源：
- 卷/章/节/定理定位：
- 与相邻版本的差异：
- 未重证边界与理由：
- 核对状态：
```

若尚未核对准确定位，应把整本书标为内容收口候选，而不是把该字段留空后宣布闭合。

## A.6 习题覆盖表

| 学习操作 | 正文示范 | 核心习题 | 解答位置 | 覆盖层级 |
|---|---|---|---|---|
| 使用定义 | 例 n.1 | En.1 | `SOLUTIONS` | 应用 |
| 检查假设 | 反例 n.2 | En.2 | `SOLUTIONS` | 比较 |
| 迁移方法 | 命题 n.3 | En.3 | `SOLUTIONS` | 迁移 |

覆盖表能发现题目很多但学习目标无人检验的情况。

## A.7 收口回执

```markdown
## 审定回执

- 审定对象与版本：
- 适用严格性标准：
- 机械检查命令与摘要：
- 核心定义抽查：
- 核心证明审读：
- 外部输入抽查：
- 例题与习题抽查：
- 已知边界：
- 判定：机械闭合 / 内容收口候选 / 内容闭合 / 不通过
```

判定必须由前述证据推出，不能预先写好再补表格。
