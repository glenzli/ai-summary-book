# 《可复现性的幻觉》写作规范

本书同时服从上级 [OET 本体严格性标准](../OET_RIGOR_STANDARD.md) 与
[人类可读教材叙事标准](../TEXTBOOK_NARRATIVE_STANDARD.md)。前者约束对象、量词、
证明和外部输入，后者约束这些内容如何进入读者的理解过程；二者不得互相替代。

## 核心纪律

1. 每个“复现”声明必须指定比较对象以及关系或判据：字节相等、数值容差、轨迹相等、统计相容或科学支持。
   精确等价关系、非传递容差、统计三值判决与科学支持关系不得混称为“等价”。
2. 程序确定性必须相对于完整输入、状态、环境与调度；不得只写“代码相同”。
   记录分量的必要性与充分性必须分开；删项反例只证明删项后的记录不充分。
3. 浮点结论必须声明格式、舍入模型、溢出/下溢和运算顺序边界。
4. 并行与分布式结论必须区分逻辑算法、调度、通信、故障恢复和外部服务。
5. 机器学习实验必须分别记录数据、初始化、批次、内核、精度、设备、checkpoint 选择和评测协议。
6. repeatability、reproducibility、replicability 在 ACM、计量学和科学方法文献中术语不同；正文必须先声明词典。
7. “复现失败”只支持与测试合同相对应的结论，不自动证明欺诈、随机性或理论错误。
8. TOST 必须写每个单侧检验的水平；在连续对称枢轴下，两个水平 $\alpha$ 单侧检验对应 $1-2\alpha$ 双侧区间。渐近版本必须标注渐近。
9. 内容身份、摘要相同、签名真实性和 provenance 闭合是不同主张。
10. 机器可执行合同必须对域外、NaN、缺失证据和边界相等给出三值或错误语义；有限判决不得升级为全域程序等价或分布真值。

## 教材叙事纪律

1. 不使用逐章固定的“本章目标”“依赖”“主线”“本章小结”栏目。预备知识和阅读路线集中写在 README 与序章；章末只在确有逻辑需要时用自然段收束并引向下一章。
2. 每章先进入一个可以追踪的故障、执行轨迹、数值计算、统计复制或合同判决，再从案例暴露的缺口引入定义。不得先列术语清单，再用一句例子装饰。
3. 每章至少包含一个完整案例或推导。系统案例要写出初态、事件、观察和分叉；数值案例要列运算次序与舍入条件；统计案例要写 estimand、模型、区间和判决；合同案例要覆盖域外、缺失与边界输入。
4. 定义和定理保留稳定编号，但前面要说明它解决案例中的什么问题，后面要说明哪个假设承担了关键工作。证明不得为叙事流畅而删减量词、类型或边界。
5. “不自动推出”“不能升级”等边界只在读者可能据当前推导误用时出现。同一边界的完整责任记录进入 `CLAIM_LEDGER.md` 或 `CLOSURE_AUDIT.md`，正文用反例或缺失假设说明具体失败原因。
6. 相邻分节必须形成诊断或构造上的推进：观察到差异，定位状态，分析数值/调度，建立统计判决，最后写成可执行合同。禁止把清单标题平行堆叠成大纲。
7. 语言采用克制的现代中文。术语可以严格，句子应能连续阅读；不用虚构课堂对话、口号或审计报告式重复声明。

## 主张终态

- 数学和程序语义命题给出完整证明；
- IEEE、框架行为和机构术语以权威规范为外部输入；
- 实验建议标为工程协议；
- 科学方法判断标为方法学论证。

## 完成检查

每章有自然导言、至少一个可跟随案例或推导、与正文对应的练习；全部解答进入 `SOLUTIONS.md`。逐章检查定义是否由问题自然引出、定理前后是否有动机与解释、结尾是否把读者送到下一章。修改后运行本书 `validate.py`、OET 审计与 `git diff --check`；验证器必须拒绝旧模板标题。
