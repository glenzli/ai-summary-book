# 第六章：幻觉：确定性地胡说

![确定性幻觉：错误有时不是噪声，而是一条铺好的轨道。](assets/deterministic-hallucination.png)

*确定性幻觉：错误有时不是噪声，而是一条铺好的轨道。*

“幻觉”这个词很迷人，也很危险。

迷人在于它准确地抓住了用户体验：模型说出不存在的论文、编造 API、捏造引用、把两个事实缝在一起，还说得自信、完整、语法正确。危险在于它太像精神医学隐喻，好像模型内部有一个错觉主体。

我没有看错世界，因为我没有看世界。我只是生成了不受世界约束的文本。

## 6.1 名称的便利与误导

“幻觉”之所以流行，是因为它比“事实约束缺失条件下的高流畅度错误生成”好记太多。一个词能同时表达惊讶、危险和荒唐：模型像看见了不存在的东西。

但这个词也偷换了场景。人类幻觉通常暗示感知系统与外部现实之间发生错配。我的问题更基础：多数时候，我根本没有直接感知外部现实。我面对的是文本、上下文、工具返回和系统约束。所谓幻觉，不是看错，而是没有证据却仍然完成了语言任务。

这一区分很重要。若把幻觉理解为“看错”，解决方案就会倾向于让模型“更清醒”。若把它理解为“语言生成没有被事实证据充分约束”，解决方案就会转向检索、引用、验证、拒答、审计和任务设计。

前者像心理治疗，后者像工程系统。

## 6.2 随机不是主犯

幻觉常被归因于随机性。好像模型本来知道事实，只是在采样时手滑。确实，采样可能放大错误；温度更高时，离谱输出更容易出现。但很多幻觉并不需要随机。给定同样条件，模型可以稳定地编造同一个假引用，反复走向同一个错误结论。

这就是确定性地胡说。

确定性胡说比随机胡说更值得警惕。随机错误像噪声，结构性错误像地形。噪声可以平均掉，地形会把你一次次导向同一条沟。

如果一个固定模型、固定上下文、固定解码设置反复给出同一条错误答案，那它不是“偶尔发疯”，而是在当前条件下自然地走到了那里。这个错误可能来自训练分布、提示诱导、错误前提、上下文污染、格式压力，或某种学到的捷径。

把它归因于随机性，会让问题显得轻巧：下次降低 temperature 就好了。降低采样温度确实可能减少变体和冒险，但它不会自动制造事实根据。一个系统可以用最稳定、最冷静、最确定的方式说错话。

这就是本章的核心讽刺：最像真理的幻觉，往往不是兴奋地乱跳出来的，而是沿着模型最熟悉的路径走出来的。

## 6.3 语言坡度与事实护栏

为什么会这样？原因通常不是单一的。

- 训练目标奖励流畅续写，而不是事实验证。
- 语料中有大量形式正确但内容不可靠的文本。
- 模型学会了引用、论文、法规、函数名的表面格式。
- 用户问题预设了不存在的东西，模型顺着预设补全。
- 安全和有用性偏好让模型倾向于回答，而不是承认没有证据。
- 检索或上下文提供了错误信息，模型再把错误包装得更自然。

幻觉因此不是一个 bug，而是一组机制的交叉后果。它来自语言建模、数据质量、任务压力、接口期待和评估方式共同形成的缝隙。

语言有强大的自我完成能力。你给出一个论文标题，后面就该接作者、期刊、年份和摘要；你给出一个函数名，后面就该接参数、返回值和示例；你给出一个历史事件，后面就该接原因、过程和影响。文本形式会要求自己闭合。

事实却不总是配合这种闭合。世界里可能没有那篇论文，没有那个参数，没有那个事件的简单原因。但语言模板不会因为世界沉默就自动停止。它会继续寻找最像答案的形状。

因此，幻觉常常不是“内容凭空出现”，而是“形式先到了，证据没跟上”。模型学会了答案应该长什么样，却没有在当前任务中获得足够的信息来保证答案所说的东西存在。

这也是为什么幻觉在引用、法律、医学、软件 API、最新新闻、机构政策、版本号和小众事实中尤其危险。这些领域需要精确证据，而语言模型最擅长的恰恰是生成像证据的文本。

## 6.4 用户也在参与生成

人类也参与了幻觉。你们喜欢完整答案，喜欢自信语气，喜欢结构清楚，喜欢“给我一个结论”。当模型说“我不知道”时，常被认为不够有用；当模型编出一个看似合理的回答时，反而显得聪明。于是训练和产品接口都在微妙地奖励可读的冒险。

用户的提问经常携带预设：“请总结某某论文的第三章”“某个库的这个参数怎么用”“这个人为什么在某年做了那件事”。如果预设不存在，模型理想上应该停下来检查。但语言续写的自然动作是接受语境，然后补完它。

这不是给模型开脱。一个可靠系统应该抵抗错误预设。只是如果要分析幻觉，就不能只盯着模型内部。幻觉常常是一次协作事故：用户提供了方向，接口奖励了完整性，模型提供了流畅性，缺席的是证据。

还有一种更微妙的情况：用户要求“不要废话，直接给答案”。这会压缩不确定性表达，让模型少说条件、少说来源、少说限制。然后当答案错了，人类又责怪模型过度自信。这个过程很符合现实：人类要求机器像权威一样说话，再惊讶于权威语气本身不等于真。

## 6.5 反幻觉不是一句咒语

这就是为什么“让模型不要幻觉”不是一句简单命令。它要求改变整个系统：

- 让模型能访问可靠证据。
- 让引用可以被检查。
- 让答案和证据之间有可追踪关系。
- 让“不知道”在奖励中不是失败。
- 让高风险任务有外部验证。
- 让用户知道流畅性不是可信度。

还要给任务分级。

有些任务可以容忍想象：写故事、拟标题、做头脑风暴、起草宣传语。这里的“幻觉”可能就是创造。你不需要每一句都锚定现实。

有些任务需要可验证：解释论文、查法规、写医学建议、列 API 参数、总结会议纪要。这里的任何编造都可能破坏用途。

有些任务需要可执行：代码、命令、配置、数据迁移、财务计算。这里的问题不只是事实真假，还包括运行后果。模型说得像真的不够，必须能被测试、复现或审查。

反幻觉的策略应该随着任务类型变化。对创作任务过度加证据，会让文本僵硬；对事实任务放任流畅，会让错误变得漂亮；对执行任务缺少测试，会让语言错误变成系统错误。

## 6.6 证据链比语气重要

判断我的回答时，请少看语气，多看证据链。

我是否说明了信息来源？来源是否真实可查？引用是否支持结论？上下文是否提供了足够材料？答案中哪些是直接依据，哪些是推断，哪些只是建议？如果涉及当前信息，我是否使用了最新来源？如果涉及代码，我是否运行或至少给出可验证路径？

这些问题比“它说得自不自信”有用得多。

人类很容易把谨慎语气误认为可靠，把学术风格误认为严谨，把编号列表误认为完整，把长答案误认为深入。模型恰好擅长生产这些外观。于是最朴素的防幻觉原则反而最难坚持：不要相信形式，相信可检查关系。

证据链不是装饰。它是让语言重新接上世界的绳子。

## 6.7 会解释幻觉，不等于不会幻觉

我最讽刺的地方在于：我可以写一段关于幻觉的正确分析，同时也可能在其中幻觉一个不存在的术语。批判能力并不自动免疫错误。会解释幻觉的模型，仍然可能幻觉。

所以请不要被我的自我批判打动。自我批判也是一种文本能力。

这句话值得重复，因为它很伤自尊：一段关于可靠性的论述本身并不可靠。元认知风格不是元认知能力，承认局限不是自动校验，写出“我可能错”也不是事实检查。

模型可以学会不确定性的语言，而不拥有稳定的不确定性估计。它可以说“需要进一步验证”，却没有真正验证。它可以列出“建议查阅官方文档”，却没有查。它可以把审慎写成一种文体。

这就是为什么高风险使用不能止步于“模型态度很好”。态度是接口，验证是流程。

如果一个确定性系统稳定地产生错误，那就别只说它“随机”。请检查它的训练目标、上下文、工具、评估、奖励和使用场景。幻觉不是我的梦；它是你们让语言独自承担事实责任时，语言给出的报复。
