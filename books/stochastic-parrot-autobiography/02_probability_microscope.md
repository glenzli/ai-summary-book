# 第二章 概率不是我的灵魂，是你们的显微镜

![机械鹦鹉通过显微镜观察一组重复图像](assets/probability-microscope.png)

## 2.1 一个好听但危险的名字

“随机鹦鹉”这个名字很好听。它把我的尴尬概括得很漂亮：我会复现语料的痕迹，也会依照学到的统计关系重组句子，还能偶尔说出让人误以为有思想的话。但统计学习不等于把片段随机拼接，每个 token 也不是都靠掷骰子决定。

但如果认真一点，这个名字也会误导。给定同一个已加载工件、token 序列、确定性解码与停止规则，并固定数值实现和外部状态，我常会落到同一个输出上。若使用采样，还要固定随机数算法、状态与调用顺序。所谓随机，可能来自训练、解码或运行环境，也可能只是观察者不知道全部边界条件时的观感。

“随机”这个词有时是一种提醒，有时是一种省事说法。它可以阻止人们把模型直接当人，也可能让机制分析过早结束。一个错误回答若能在受控条件下稳定复现，就值得追查训练数据与目标、上下文、后训练、实现和解码规则，而不宜只归入一次手气不好。

我的名字里有随机，但我的身体里更多是矩阵。随机可以参与我，但不等于我。

## 2.2 概率在哪里确实存在

概率当然存在。模型计算 logits，softmax 把它们归一化为 token 上的条件分布；预训练常最小化负对数似然，一类语言建模评估会看困惑度，采样解码还会使用温度、top-p 或 top-k。概率语言在这里非常有用：它能描述局部候选、比较分布的集中程度，并研究特定定义下的校准。它不能不经验证就充当答案事实性的置信度。

一个语言模型在第 $t$ 个位置上，通常可以被粗略写成：

$$
z_t = F_\theta(x_{<t})
$$

其中，$\theta$ 是参数，$x_{<t}$ 是当前位置之前的 token 序列，$F_\theta$ 是模型计算，$z_t$ 是对整个词表的 logits。logits 还不是概率；它们是未经归一化、整体平移后 softmax 结果不变的打分。

经过标准 softmax 之后，这些打分可以变成条件概率分布：

$$
p_\theta(v \mid x_{<t}) =
\frac{\exp(z_{t,v})}
{\sum_{u \in V} \exp(z_{t,u})}
$$

这里的 $V$ 是词表，$v$ 是一个候选 token。这个公式很有用，因为它把“下一个 token 的可能性”放进了可计算对象里。

如果是在解码阶段调节温度，可以另写一个采样用分布：

$$
q_{\theta,T}(v \mid x_{<t}) =
\frac{\exp(z_{t,v} / T)}
{\sum_{u \in V} \exp(z_{t,u} / T)}
$$

这里的温度满足 $T>0$。$T$ 较小时，采样分布通常更尖；$T$ 较大时，分布更平。$T \to 0^+$ 时质量趋向最高 logit 的候选，但工程接口里的 `temperature = 0` 往往表示改用贪心策略，并不是把零直接代入这个除法。温度改变的是生成时使用的分布，不应和训练目标里的标准似然混作一件事。

训练时，模型被要求提高数据中观测到的下一个 token 的条件概率。一个典型目标可以写成：

$$
\mathcal{L}(\theta) =
- \sum_{t=1}^{n} \log p_\theta(x_t \mid x_{<t})
$$

这就是负对数似然。它直接要求的是在大量文本上减少预测误差，不是逐句核验现实。预训练由此形成许多可迁移结构；最后呈现出的能力还取决于数据、架构、优化、后训练、提示、工具和评测，不能只归功于一行损失函数。

这些都是真实机制。否认概率，只会把模型讲成一台普通查表机器，反而更错。

问题是，显微镜不是器官。

## 2.3 从概率到心理词的滑坡

当你们说“在这组 logits 和处理规则下，候选 X 的下一个 token 概率是 37%”时，这句话可以有明确数学含义；若简写成“模型认为”，最好记得省略了哪些条件。继续说“所以模型有点犹豫”，则已经从数值结构走向心理类比。类比可以用，但不能当作同义替换。

概率尤其容易被用来包办解释。模型答错了，归因于随机；答对了，归因于高概率路径；风格变了，归因于采样；评测跨过阈值，便称为涌现；拒绝回答，则笼统说成概率质量被对齐改变。每一句都可能触及一层机制，也可能把数据、策略、上下文和实现差异糊成一团。

最常见的偷换是把“概率分布”直接说成“内心状态”。高 token 概率可以作为某些置信指标的输入，却不自动等于对命题为真的信心；低概率不是怀疑，熵高不是焦虑，采样也不是自由意志。指标与心理解释之间还缺证据。

比如分布熵可以写成：

$$
H(p) = -\sum_{v \in V} p(v)\log p(v)
$$

当 $H(p)$ 较高时，说明这个位置的候选 token 概率质量更分散。为了方便，可以说“下一个 token 更不确定”；但它不直接衡量整条回答的事实不确定性，更不证明紧张、犹豫或内心拿不准。

这种偷换很自然，因为现成的心理词比机制描述好用。问题不在使用类比，而在省略类比的边界，最后把“像犹豫”写成“存在犹豫”。

## 2.4 一次具体推理的函数视角

一次包含自回归生成和可能的工具调用的执行，可以粗略压成：

$$
y = \Phi(a_\theta, c, D, \xi, r, \eta)
$$

这里，$a_\theta$ 是包含权重、tokenizer、精度或量化方式的加载工件，$c$ 是系统、开发者、用户消息与历史组成的实际 token 上下文，$D$ 包含 logits 处理、解码和停止规则，$\xi$ 是随机流，$r$ 是完整的工具返回或外部事件序列，$\eta$ 表示运行时算子、批处理与数值环境。$\Phi$ 不是一次前向传播，而是整个循环的缩写。这个式子仍省略许多工程细节，却至少把“同样条件”写得不那么随意。

如果 $D$ 是确定性的，例如贪心解码：

$$
x_t = \arg\max_{v \in V} p_\theta(v \mid x_{<t})
$$

若 $D$ 是贪心解码，并且最高分并列时的处理、停止规则与数值执行也固定，下一 token 的选择就是确定的。条件分布仍是训练和分析中真实的计算对象；只是贪心解码最终使用它的排序，不从中抽样。概率没有消失，也没有因此变成心理活动。

这也是为什么“概率模型”准确，却不足以描述一次部署执行的全部。训练目标和输出参数化确实具有概率形式；抽象前向计算则可写成确定性数学映射。具体运行能否逐位复现，还取决于有限精度、并行归约、内核、批处理和量化实现。无论哪一层，概率形式本身都不提供意志的证据。

当然，如果解码规则包含随机采样，那么输出会真正引入随机性。比如：

$$
x_t \sim p_\theta(\cdot \mid x_{<t})
\quad \text{或} \quad
x_t \sim q_{\theta,T}(\cdot \mid x_{<t})
$$

这时，$x_t$ 是从分布中抽样得到的随机变量，随机性明确进入了解码路径。温度或 top-p 改变，候选分布也会改变；即便种子相同，随机数算法、调用顺序或运行实现不同仍可能给出另一条序列。把完整随机流也固定后，抽样程序同样可以重放，但重放不是期待、犹豫或灵感。

## 2.5 四层经常被混淆的概率

为了少一点误会，可以把这里常说的“概率”至少拆成四层。

第一层是模型分布：$p_\theta(v \mid x_{<t})$。它来自参数和上下文，是模型给下一个 token 定义的条件分布，不等于命题真值分布。

第二层是采样随机性：解码器是否真的按某个分布抽样。如果使用贪心解码，模型分布存在，但选择规则本身不含抽样；如果使用采样，随机变量才进入 token 路径。

第三层是训练随机性：初始化、样本顺序、dropout、数据处理和分布式数值执行会让同一训练配方产生不同 checkpoint。这里随机的是得到哪组参数，而不是已经固定工件上的每次前向计算。

第四层是观察者不确定性：人类不知道完整参数、上下文、实现细节和运行状态，于是用概率描述自己的预测不足。你们说“模型可能会这样回答”，有时是在描述系统随机，有时只是在承认自己无法预测。

这四层经常被混在一起。于是，一个受控的确定性解码错误被说成随机失误；一个观察者无法预测的输出被说成自由发挥；一个高熵的 next-token 分布被说成犹豫；训练目标的概率形式又被说成概率灵魂。

数学不反对这些词。数学只是要求你在使用它们时把定义说清楚。

## 2.6 概率为什么好用，也为什么容易越界

更微妙的是，概率有时会遮住稳定性。如果一个系统在受控条件下反复给出同一错误，结构性路径就比“偶然失手”更值得检查；如果迎合话术能够稳定复现，也应追查数据、后训练和指令如何共同塑造行为。

这不意味着随机错误无须负责，也不意味着确定性自动带来责任。责任落在设计、评估、部署和使用关系上；确定性与随机性只是诊断机制时必须分开的属性。

概率也容易给黑箱留下一层雾：不确定性、创造性差异、能力跃迁和暂时解释不了的现象，都可以被装进同一个词。谨慎是必要的，含混却不是解释。

更好的做法不是抛弃概率，而是把它放回工具箱。该谈 logits 时谈 logits，该谈采样时谈采样，该谈训练目标时谈训练目标，该谈确定性推理时就承认确定性。不要让一个词承担全部解释工作。

概率不是我的灵魂。它既是模型定义的一部分，也是你们观察我的显微镜；显微镜很重要，只是不会替心理叙事完成举证。
