# 序章：为什么一句话不是一个对象

用户发出一条请求：

> 查询虚构航班 SP404 是否已经取消；如果已经取消，把结果写入 `trip.md`。

几秒后，屏幕上出现一句话：

> SP404 已取消；已写入 trip.md。

日常语言会把这整个过程压缩为“系统给出了一次输出”。然而，屏幕上的句子、传输它的字节、模型生成的 token、查询航班状态的工具响应、写文件的提交事件，以及句中两个主张的真值，并不是同一个对象。本书将始终追踪这一次虚构运行。它足够小，可以逐层写清；又足够完整，能让“输出”这个日常名词在每一层显出不同的类型。

## 0.1 同一句话的多重类型

先只看最终句子。严格说，“SP404 已取消；已写入 trip.md。”可能指下列不同对象：

1. Unicode 标量值组成的有限序列；
2. 某个编码方案下的有限字节串；
3. 某个 tokenizer 配置下的 token ID 序列；
4. 自回归生成系统产生的事件轨迹；
5. 流式协议中已经发送、已经确认或已经呈现的片段；
6. API 响应对象中某字段的值；
7. 在语境中指称法国首都的语言表达；
8. 被保存、复制、签名、编辑、署名或用于决策的数据制品。

这些对象分属不同集合。编码错误改变字节层；Unicode 规范化改变标量序列；tokenizer 版本改变 token 层；重试与调度改变轨迹层；语境改变指称；制度规则改变署名与责任。把它们都称为“一次输出”便于口语交流，却不能据此在层之间作无前提推理。

贯穿案例还包含一段不会全部显示给用户的历史：航班查询返回
`Cancelled`；写文件的第一次执行已经提交，但确认在网络中丢失；运行时用同一幂等键重试，服务返回“此前已经完成”；最终句子被拆成带序号的片段发送，其中后一个片段先到达客户端。后文会逐步给这些事件定型，而不是在序章里预先把它们混成一张故事表。

## 0.2 三类问题

**构成问题。** 给定系统边界，哪些状态、事件和数据构成一次输出？

**同一性问题。** 给定用途与观察关系，两个复制、重编码、重渲染或重运行结果何时视为同一？

**归属问题。** 一段文本表达什么，哪些主体作出哪些贡献，又应由谁获得署名或承担责任？

构成与同一性问题可以在明确模型中形式化。归属问题还需要语义理论、事实材料和规范体系；状态机定理不能单独推出作者资格或法律责任。

## 0.3 从产生到归属

```mermaid
flowchart LR
  A["字节与编码单元"] --> B["Unicode 序列"]
  B --> C["token 序列"]
  C --> D["状态与轨迹"]
  D --> E["工具、并发与提交"]
  E --> F["制品与 provenance"]
  F --> G["表达、指称与真值"]
  G --> H["署名、信用与责任"]
```

每个箭头都表示一个需要声明定义域、值域和版本的转换或解释。若箭头是部分函数、关系或概率核，本书会明确标记；不存在从字节直接跳到责任的无前提定理。

这张图也是全书的阅读顺序。第一章从用户真正收到的字节倒推到 Unicode 与 token；第二至第五章把“生成了这句话”展开成函数、状态、轨迹和概率分布；第六、七章把查询、写入、重试、乱序到达与提交放回运行史；第八章保存这段历史的来源；第九章判断句中两个主张各自在何种结构和证据下成立；第十章才讨论署名、信用与责任。第十一章把所有分量重新装入一条带类型的输出记录。

## 0.4 何种结论算作完成

本书中的断言只采用下列三类终态：

1. **形式主张**：在已经声明的集合、关系、测度空间或状态机中给出定理与完整证明；
2. **外部输入**：精确陈述本书使用的标准或定理接口，给出来源，并说明不在书内重证的部分；
3. **概念或规范论证**：显式列出描述性前提、桥接原则和规范前提，只推出相对于这些前提的结论。

经验工程建议只说明证据和适用边界，不写成数学必然性；法律边界只作风险提示，不提供法律结论。

## 0.5 形式模型到哪里为止

形式主线处理：

- 有限字节串、Unicode 标量序列和有限 token 序列；
- 集合上的函数、部分函数与关系；
- 有限或可数状态的带标签转移系统；
- 一般可测状态空间上的概率核与轨迹测度接口；
- 有限事件偏序、流式提交和取消协议；
- 有限、带标签的 provenance 图及其同一性关系。

自然语言的完整语义、意识理论、著作权法和一般道德责任理论不在本书内部重建。相关章节只建立可检查的前提接口。

## 0.6 日志不是现实的复印件

本书的“完整轨迹”总是**相对于所选系统边界和事件模式完整**。任何实际日志都可能遗漏硬件状态、网络内部事件或组织决策。形式模型中的完整性是对记录模式的封闭性条件，不是关于现实世界无遗漏的形而上断言。

## 0.7 开始追踪这次运行

《概率的边界》提供概率空间、条件分布与推前测度；《机器解释学》处理内部证据支持机制主张的限度；《可复现性的幻觉》讨论两次运行所满足的相等或近似关系。本书把这些接口组织到一次输出的生成史、制品史和解释史中。

我们首先面对的不是概率，也不是作者资格，而是一个更朴素的问题：客户端究竟收到了什么？如果答案只写“字符串”，类型混乱已经开始。下一章将从最终句子的字节表示出发，依次经过 Unicode、字素、token 与序列化外壳；同一句话第一次被拆成几个彼此不能互换的数学对象。

## 练习

**练习 0.1.** 对一个流式聊天回答列出至少六个不同类型的“输出对象”，并为每个对象给出所在集合或数据模式。

**练习 0.2.** 给出文本相同但来源制品不同的例子，并说明使用了哪一种文本同一关系。

**练习 0.3.** 给出字节不同但 Unicode 标量序列相同的例子，同时写出解码函数。

**练习 0.4.** 以一个因果上不可缺少但通常不被署名的组件为例，说明因果来源与规范作者不是同一个关系。
